# Project Garden

локальный сад для проектов, заметок и следующих шагов.

вместо таблицы здесь — растения. выберите проект, обновите его паспорт и закройте вкладку: данные останутся в этом браузере.

## что умеет

- добавлять, редактировать, дублировать и удалять проекты;
- показывать состояние проекта: рост, пауза или архив;
- искать по названию, описанию, заметке, следующему шагу и именам файлов;
- сортировать сад по дате обновления, названию или состоянию;
- сохранять данные в IndexedDB и резервное локальное зеркало;
- импортировать JSON и ZIP. ZIP читается по центральному каталогу: приложение получает только имена, расширения, размеры и даты, не распаковывает файлы и не запускает их;
- экспортировать полный сад в JSON и делать PNG-снимок со всеми растениями;
- работать через обычный выбор файла, если браузер не поддерживает дополнительные File System API.

данные не отправляются на сервер. приложение не обращается к GitHub API и не обещает синхронизацию между устройствами.

## запуск

сборка не нужна. откройте папку через любой статический сервер:

```bash
python3 -m http.server 4173
```

затем откройте [http://localhost:4173](http://localhost:4173).

из-за модулей JavaScript лучше использовать сервер, а не открывать `index.html` двойным кликом.

## публикация на GitHub Pages

в репозитории уже есть workflow `.github/workflows/pages.yml`. после первого push включите GitHub Pages с источником **GitHub Actions** — workflow опубликует содержимое корня.

если репозитория ещё нет:

```bash
git init
git add .
git commit -m "initial project garden"
git branch -M main
git remote add origin <адрес репозитория>
git push -u origin main
```

## ограничения импорта

- JSON: до 5 МБ и до 500 проектов;
- ZIP: до 100 МБ, до 10 000 записей, до 500 МБ распакованного размера и до 500 сохранённых имён;
- небезопасные пути вроде `../secret.txt`, абсолютные пути и управляющие символы отклоняются.
