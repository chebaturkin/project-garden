# project garden — дизайн-система и сценарий

## Направление

project garden — локальный ботанический атлас для короткого обзора проектов. Сад — главный экран: растения стоят на общей почве и меняют силуэт по статусу и возрасту проекта. Детали открываются только после выбора растения, чтобы интерфейс оставался сценой, а не дашбордом.

## Дизайн-система

- Палитра: молочный фон `#f5f0e6`, мшистый `#445344`, шалфей `#a8b7a1`, терракота `#b7644a`, охра `#c89b4b`, чернила `#2f322c`.
- Типографика: Fraunces для названий и заголовков; Azeret Mono для дат, статусов, путей и технических меток; системный sans для длинного описания.
- Формы: плоские SVG-силуэты растений, тонкие контуры, бумажные штрихи, горизонтальная грядка. Градиенты, стеклянные карточки, pill-навигация и KPI-плитки исключены.
- Пространство: двухколоночная сцена на desktop; на mobile сцена и инспектор складываются вертикально. Выбор растения виден через тонкий контур и текстовый бейдж.
- Состояния: active — прямой стебель и открытые листья; sleeping — наклонённый стебель и закрытая почка; archived — сухой стебель и семенная коробочка.

## Сценарий

1. Человек нажимает «Добавить растение», заполняет название, статус, цвет и при желании заметку/следующий шаг.
2. После сохранения растение появляется на грядке и остаётся выбранным.
3. Фильтр «Все / Активные / В спячке / Архив» обновляет только сцену.
4. Поиск проходит по названию, описанию, заметке, следующему шагу и следам ZIP; сортировка доступна по обновлению, названию и состоянию.
5. В инспекторе можно изменить поля, дублировать или удалить проект; все изменения сразу сохраняются в IndexedDB.
6. JSON импортируется из файла. ZIP анализируется безопасно по центральному каталогу без распаковки.
7. Экспорт JSON скачивает переносимый набор данных; «Снимок PNG» рисует локальную сцену на canvas.
8. При следующем открытии вкладки сад восстанавливается из IndexedDB или резервного локального зеркала.

## Архитектура MVP

- Статический сайт без сборщика: `index.html`, `styles.css`, `app.js`.
- Репозиторий IndexedDB `project-garden`, store `projects` и метаданные ревизии; localStorage хранит версионное зеркало.
- JSON-модель проекта: `id`, `name`, `description`, `color`, `status`, `updatedAt`, `note`, `nextStep`, `files`.
- ZIP-парсер читает только central directory; содержимое файлов недоступно приложению.
- File System Access API используется только как прогрессивное улучшение, базовый сценарий — обычные `input[type=file]` и скачивание Blob.

## Доступность и устойчивость

- Все действия доступны с клавиатуры, фокус видим, статусы продублированы текстом.
- `prefers-reduced-motion` отключает анимации.
- Пустой сад, неподдерживаемый файл и повреждённый ZIP показывают объяснимое состояние в live-region.
- JSON ограничен 5 МБ и 500 проектами; ZIP ограничен 100 МБ архива, 500 МБ заявленного распакованного объёма и 500 показанными файлами.
- Адаптивная сетка проверяется на desktop и узких экранах; длинные названия не ломают сцену.
